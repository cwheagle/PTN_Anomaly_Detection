# 성능 평가 보고 (시뮬레이션 기준)

> **이 문서의 모든 수치는 시뮬레이터가 만든 데이터에서 측정한 값입니다.** 실제 망의 장애 모양, 노이즈, 유병률은 다를 수 있고,
> 실데이터 성능은 아직 검증되지 않았습니다. 수치는 "모델의 상대적 강약점과 개선 효과를 비교"하는 용도입니다.
> (plan.md Backlog P1-2: 실데이터 검증 준비)

- 평가 방식: `validation/cli/evaluate_model.py`, `validate_policy.py`, `sensitivity.py` (이벤트 단위 지표, 시드 고정, 학습과 분리된 데이터)
- 데이터: 60포트 × 14일, 에피소드 약 100건, 유병률 약 4~5% (조건별로 변경)
- **개발용**(정책 선택에 사용): 시드 7, 11 (노이즈 포함/제거) / **검증 전용**(선택 후 처음 사용): 시드 23, 31, 47 / **민감도용**: 시드 101, 102

## 1. 구 평가(F1 0.84~0.86)에 대한 정정
구 평가는 포트×시간의 93.9%가 정답 구간이라 오탐이 구조적으로 불가능했고("항상 알람"이 F1 0.97), TP의 91%가 사후 알람이었으며,
평가 기간이 학습 기간과 겹치고 학습 데이터가 오염되어 있어 모델 성능의 근거가 될 수 없습니다. 같은 모델을 새 평가로 재측정하면 이벤트 F1 **0.325**입니다.

### 선택 규칙 (사전 정의)
개발용 4개 데이터에서 `조기 탐지율 ≥ 70%` 이고 `오탐 ≤ 0.02건/포트·일`인 정책 중 이벤트 F1이 최대인 것 → **임계치 배율 3.0 / σ 2.0 / 댐프닝 MINOR 6·MAJOR 4·CRITICAL 3연속**.
(F1만 최대화하면 조기 탐지율이 56~62%까지 내려가는 정책이 선택되어 예지 목적에 어긋나므로 제약을 두었습니다.)

## 5. 시도했으나 채택하지 않은 것: 장시간 수렴 학습
정상 변동 포함 학습을 100에폭(배치 128, 인내 10)까지 돌린 모델은 검증 손실이 낮아졌지만(트래픽 0.0451 → 0.0337, 광 0.0251 → 0.0166)
**구분력(AUPRC)이 같았고**(트래픽 0.592 vs 0.588, 광 0.675 vs 0.695) 이벤트 F1은 0.746 ± 0.014로 오히려 낮았으며 선택 규칙을 만족하는 정책이 없었습니다.
→ 재구성 오차가 낮아지는 것과 이상 구분이 좋아지는 것은 별개입니다. 단, 배치 크기와 인내 횟수를 함께 바꾼 실험이라 "수렴 자체의 효과"라고 단정할 수 없습니다.

## 6. 한계와 주의
1. **시뮬레이션 수치입니다.** 장애 모양, 노이즈 크기는 가정이며 실데이터 성능은 미검증입니다.
2. 선택한 정책은 **새로 학습한 모델(noisy)과 짝**입니다. 현재 운영 중인 v1(오염된 구 모델)에는 맞지 않으며, 모델 승격(P1-3)과 함께 적용해야 합니다. 기본 정책은 변경하지 않았습니다(`src/config.py.example` 의 `ALERT_POLICY` 주석에 프리셋만 문서화).
3. 오탐 억제와 예지(조기 탐지·리드타임)는 **상충**합니다. 어느 쪽을 더 중시할지는 현장 정책 결정입니다.
4. 롤링 규칙의 임계값은 시뮬레이터의 장애 범위를 알고 정했으므로 중립적인 비교 대상이 아닙니다.
5. 트래픽 감소 탐지는 개선이 필요합니다 (Backlog P1-4).

## 7. 재학습 데이터 자동 정제 검증 (P1-1 D, 2026-10-06)
설계: `docs/design/p1_1_retrain_pipeline.md` 6.1·6.2. 재학습 시 학습 데이터에서 장애 의심 구간을 자동으로 빼는 방식(A: 자기 알람 구간, B: 모델과 무관한 규칙, C: 명시 CSV)이
장애를 충분히 걸러내는지, 그렇게 학습한 모델이 정답 기반 정제 모델만큼 좋은지 확인했습니다. 이 장의 수치도 **시뮬레이션 기준이며 실데이터 검증이 아닙니다.**

### 7.1 의심 구간 품질 (`validation/cli/check_retrain_policy.py`)
기준(데이터를 보기 전에 고정, lessons #30): 장애 스텝 제외율 ≥ 90%, 정상 교란(nuisance) 스텝 제외율 ≤ 10%, 전체 제외율 < 20%.
규칙 B 의 파라미터는 개발 시드 7·11 에서 격자 81개로 선택하고, 검증 시드 23·31·47 로 확인했습니다.

선택 규칙(`check_retrain_policy.py` docstring 에 데이터를 보기 전에 고정):
- 개발 시드 7·11 **모두**에서 위 세 기준을 통과한 후보 중 nuisance 제외율(두 시드 평균) 최소 → 동률이면 장애 제외율 최대 → 동률이면 설계서 기본값에 가까운 쪽.
- 통과 후보가 없으면 **(장애 제외율 − nuisance 제외율) 평균이 최대인 후보**를 고르고 "기준 미달"로 보고. (코드상 동률이면 기본값과 다른 파라미터 수가 적은 쪽)
- 선택 후 검증 시드에서 확인하며, 검증 결과로 파라미터를 다시 고르지 않음.

결과:
- **개발 시드에서 기준을 통과한 후보: 0/81** → 폴백 규칙으로 **error_ge 10 / rx_drop 2dB / traffic_ratio 0.3 / 연속 6스텝** 선택, 코드 기본값으로 채택(`src/pipeline/retrain_policy.py`).
- 선택값의 개발 시드 장애 제외율: 시드 7 89.4%, 시드 11 89.8% (둘 다 90% 미달).
- 설계서 기본값(error_ge 20 / rx_drop 3dB / traffic_ratio 0.15 / 연속 4스텝)의 개발 시드: 장애 제외율 85.1%, nuisance 0.8%.
- 기준(장애 ≥ 90%)은 완화하지 않았습니다.

규칙 B 단독, 검증 시드 (제외율 %)
| 시드 | 장애 | nuisance | 전체 | 판정 |
|---|---|---|---|---|
| 23 | 90.7 | 1.8 | 2.9 | PASS |
| 31 | 89.6 | 0.9 | 3.5 | **FAIL** (장애 < 90) |
| 47 | 91.6 | 1.4 | 3.3 | PASS |
| 평균 | 90.6 | 1.3 | 3.3 | 경계선 (3시드 중 2 PASS) |

- **원인: traffic_drop 이 약하게 걸러짐.** 장애 유형별 제외율이 crc·optical 은 약 100%인 반면 traffic_drop 은 설계서 기본값 13~22%, 선택값 31~54%.
  규칙이 "직전 24시간 중앙값 대비"로 판단하는데, 점진적 감소에서는 중앙값이 감소를 따라 내려가 비율이 기준에 닿지 않습니다. 4장의 트래픽 감소 취약점(P1-4)과 같은 구조입니다.
- 명시 구간(C, 정답 에피소드를 CSV 로 주입): 장애 100% / nuisance 2.9% / 전체 7.1%, **전 시드 PASS**.

A 와 A∪B 의 장애 제외율 (7.2 의 각 학습 모델을 활성 모델로 가정해 A 를 산출, 반복 2회 값)
| 활성 모델 | A 단독 | A∪B | B 단독 |
|---|---|---|---|
| auto 로 학습한 모델 | 0.81 / 0.80 | 0.913 | 0.906 |
| truth 로 학습한 모델 | 0.795 / 0.808 | — | — |
| none(제외 없음)으로 학습한 모델 | 0.24 / 0.17 | — | — |

- A 가 B 에 더하는 효과는 약 +0.7%p 로, 장애 제외는 주로 규칙 B 가 담당합니다.
- 제외 없이 학습한 모델의 A 는 0.17~0.24 → **장애를 학습한 모델일수록 자기 알람으로는 장애를 걸러내지 못하는 순환 위험**(설계서 8장)이 시뮬레이션에서 실제로 나타났습니다.

### 7.2 정제 방식별 학습 모델 품질 (`validation/cli/compare_train_exclusion.py`)
조건: **제외 방식만 변경** — truth(정답 기반 제외) / auto(A∪B 자동 의심 구간 제외) / none(제외 없음). 같은 학습 데이터(noisy, 4노드 21일),
30에폭·배치 64·인내 5, 검증 시드 23·31·47, 반복 2회. 표의 값은 "반복1 / 반복2".

| 지표 | auto | truth | none |
|---|---|---|---|
| AUPRC (선택 정책) | 0.641 / 0.632 | 0.621 / 0.603 | 0.149 / 0.159 |
| 이벤트 F1 (선택 정책) | 0.812 / 0.798 | 0.783 / 0.754 | 0.013 / 0.020 |
| 오탐/포트·일 (선택 정책) | 0.008 / 0.012 | 0.015 / 0.029 | — |
| 이벤트 F1 (기본 정책) | 0.652 / 0.664 | 0.633 / 0.610 | 0.568 / 0.424 |

합격 기준(설계서 6.2: auto 가 truth 대비 AUPRC·F1 −0.05 이내, none 보다 나음): **4건 모두 PASS**
(auto − truth: AUPRC +0.020 ~ +0.029, F1 +0.019 ~ +0.054, auto > none).

- **단서**
  - 반복 2회뿐이므로 ±0.03 이내 차이는 우열의 근거가 아닙니다. "auto 가 truth 이상"이 아니라 **"auto 가 truth 에 뒤지지 않음"** 까지만 주장할 수 있습니다.
  - auto 가 truth 보다 높게 나온 이유로 의심 구간 확장(앞 16·뒤 4스텝)이 장애 전후 램프를 더 많이 제외했을 가능성을 **추정**하지만, 분리 실험은 하지 않았습니다.
  - none 모델은 임계치가 높아져 선택 정책에서 거의 아무것도 잡지 못했습니다(조기 탐지 0~0.3%). **장애 구간을 정상으로 학습하면 모델이 둔감해진다**는 위험을 실증합니다.
- 7.1 의 traffic_drop 제외 부족(B 의 경계선 미달)이 있었음에도 모델 품질 기준은 통과했습니다. 다만 traffic_drop 위주 환경에서는 이 결과가 유지된다고 볼 근거가 없습니다(미측정).
