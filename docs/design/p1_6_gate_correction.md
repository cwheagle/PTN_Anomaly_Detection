## 1. 배경과 범위
- P1-3 V3 FAIL(2026-10-06) 후 G3 는 정보·보조 신호(P1-3 5.3), V5(2026-10-07)에서 G2 의 '너무 좋아진 쪽' 한계 확인(P1-3 2.4-1·10장). 그동안 승격 판단은 V1·V2·V4 오프라인 검증, G4 카나리, 사람 검토, 승격 사유 기록(P1-3 7장 3~4)에 둔다.
- 범위: (1) G3 의 상대 판정 대안 비교, (2) G2 검증 손실 판정의 방향 보완, (3) 채택 시 구현 단위. **범위 밖**: G1·G4·G5 변경, 알람 정책·임계치 산출(P1-5 종료), 카나리 구성, traffic_drop 판별(P1-4), 실데이터.

## 2. 선행 확인 — 현재 게이트 코드 사실 (2026-10-07, 코드로 확인)

### 2.1 공통 (`src/models/promotion_gate.py`, `src/models/registry.py`)
1. 게이트는 학습 직후 1회 실행해 레지스트리 엔트리 `gate` 에 저장, 승격은 저장값을 쓴다. `POST /api/model/gate` 로 재실행(`src/api/main.py` `run_gate_for`).
2. 종합: FAIL > WARN > PASS, **G3 SKIP 은 종합 WARN**, 다른 SKIP 무시(`overall_status`, 62-70). **auto 는 PASS 에서만 승격**.
3. 승격(`registry.promote` 253-267 → `_gate_findings` 221-243): G1 FAIL 은 force 로도 불가, **그 밖의 FAIL·ERROR 는 차단 사유(409, force 로 진행)**, WARN 은 승격하고 메모로 반환. 게이트의 비교 대상(`data.against`)이 현재 활성과 다르면 G2 차단 사유를 버리고 `compare_with_active` 로 다시 계산(lessons #34). 게이트가 없으면 `compare_with_active` 만 적용.

### 2.2 G2 (`check_g2` 92-101 → `registry.compare_with_active` 194-209)
1. 임계치: `tc/ta > 3` **또는** `< 1/3` 이면 경고(**양방향**). 상수 `THRESHOLD_RATIO_LIMIT = 3.0`(34).
2. 검증 손실: `vc/va > 3` 일 때만 경고(**나빠지는 쪽만**). 상수 `VAL_LOSS_RATIO_LIMIT = 3.0`(35). 어느 한쪽이 없거나 0 이면 비교 안 함. → **plan.md P1-6 ② 의 전제와 일치**.
3. **추가 사실(전제 보완)**: `final_val_loss` 는 각 모델의 **자기 검증 데이터**에서 구한 best 검증 손실(전 타임스텝 평균, `trainer.py:107-172`, `:321`)이다. 후보는 학습 당시의 홀드아웃 포트, 레거시 v1 은 다른 분할·데이터·스케일러 버그 수정 전(lessons #25) 산출물이다. 따라서 **검증 손실 비율은 같은 데이터에서 잰 비교가 아니며**, "후보가 비정상적으로 낮다" 와 "검증 데이터가 쉬웠다/달랐다" 를 구분하지 못한다. 활성 v1 의 3.01 이 왜 높은지는 **확인하지 않았다**(스케일러 버그 영향은 추정).
4. G2 FAIL 은 차단 사유(force 필요). G2 경고 문자열은 임계치·검증 손실 각각 한 줄.

### 2.3 G3 (`check_g3` 114-142, 데이터는 `run_gate` 245-305)
1. 데이터: `plan_window` 의 **최근 `gate_days`=3일**(`train_window.py:36`) 원본을 DB 에서 그대로 조회(`_fetch_raw_for_gate`, **정제 없음 → 실제 장애 구간 포함**), 홀드아웃 포트만(`_sample_ports`, salt `ptn`·10%, 최대 2000포트).
2. **후보·활성 모두 같은 원본·같은 구간**을 각자의 모델·각자의 알람 정책으로 점수화(274-289, P1-3 4.2-6) → `alerting.alarms_from_track_scores` → `count_incidents` 로 인시던트/포트·일.
3. 판정(C4'): 포트·일 < 150 이면 SKIP(→ 종합 WARN) → 상대 기준 `cand > max(active × 1.5, 0.01)` 이면 **FAIL** → 아니면 `cand > 0.05` 이면 **WARN** → PASS. 상수 `retrain_policy.py:62-65`.
4. **알람 단위 겹침** `overlap_with_active`(후보 알람 행 중 같은 포트·시각에 활성도 알람인 비율)를 계산해 `data.candidate_stats` 에 저장하지만 **판정에 쓰지 않는다**(290-293).
5. "G3 = 정보·보조 신호" 는 P1-3 5.3 의 **문서상 지위**다. 코드는 바뀌지 않아 **상대 FAIL 은 여전히 차단 사유(force 필요)**, WARN 은 auto 차단.
6. **비대칭(사실 + 미검증 영향)**: 게이트 포트는 후보에게는 학습에서 뺀 홀드아웃(조기 종료에만 사용)이지만, 활성 모델에게는 학습 포트였을 수 있다(다른 salt·레거시 v1 은 전 포트 학습). 활성의 알람이 그만큼 적게 나올 수 있으나 측정하지 않았다.

## 3. 사전 고정 원칙 (이 설계서의 전제)
1. **P1-3 결과를 다시 고르지 않는다**: V3 FAIL·G3 정보 신호 강등, V5 G2 PASS 는 기록 그대로. P1-6 의 어떤 결과도 P1-3 판정을 바꾸지 않는다(plan.md P1-6, lessons #37).
2. 대안은 2.4 의 이미 연 데이터를 보고 떠올렸다 → 그 데이터(시드 23·31·47)로 대안을 고르거나 판정하지 않는다. **선택은 개발 데이터, 판정은 미개봉 근거 데이터 1회**(#30).
3. 판정 기준은 **데이터를 열기 전에** 11장 결정으로 확정하고, 이후 변경은 6.4 규칙만.
4. 근거 실행은 **1회**, 코드 잠금으로 강제(P1-3·P1-5 `evidence_lock`·`check_record` 방식, #38).
5. 한 번에 하나: G3 대안은 **상대 FAIL 판정식만** 바꾸고 최소 포트·일 가드·절대 상한 WARN·종합 규칙은 그대로. G2 대안은 **검증 손실 판정만** 바꾸고 임계치 양방향은 그대로.

## 5. 대안 (게이트별, 한 번에 하나)

### 5.1 ① G3 — 상대 FAIL 판정식만 교체 (가드·절대 WARN·종합 규칙 고정)
| ID | 대안 | 판정식 (상대 FAIL 자리) | 추가 계산 | 장점 | 약점(사전 고지) |
|---|---|---|---|---|---|
| C4' (현행) | 비율 | `cand > max(active × 1.5, 0.01)` | — | — | 진짜 장애 알람에 희석(2.4) |
| **G3-A** | **증가분** | `cand − active > δ` | 없음(이미 있는 두 값) | 가장 작은 변경, 희석 없음 | 활성이 과다(v1)면 Δ<0 → 첫 승격에선 판별 안 됨(R3 은 절대 WARN 이 담당). 활성 알람이 비대칭으로 적으면(2.3-6) 정상 후보도 Δ>0 |
| **G3-C** | **후보만의 새 알람** | 후보 인시던트 중 **같은 포트·시간에 활성 알람과 겹치지 않는 것**의 비율(건/포트·일) `> ν` | 인시던트 단위 겹침(현행 `overlap_with_active` 는 행 단위 → 인시던트 단위로 새로 계산) | 둘 다 잡는 진짜 장애는 빠짐 | 후보가 활성이 놓친 **진짜 장애를 새로 잡아도 벌점**(개선을 막음 — 예: v2 의 조기 탐지). 겹침 허용 시간(±k 스텝) 값이 추가로 필요 |
| G3-B (보류 권장) | 규칙 의심 구간 밖 증가분 | (규칙 B 의심 구간 밖 후보 인시던트) − (같은 활성 값) `> δ` | `train_window.intervals_from_rules` | 정답 없이 장애 구간 일부 제거 | P1-3 에서 폐기한 C3 의 상대판. 규칙 B 의 광 열화 커버리지 한계(P1-3 5.2) 가 남고 규칙 의존이 추가됨 |

- δ·ν 는 **개발 시드에서 사전 고정 선택 규칙으로 고른다**(6.2): 후보 격자 δ, ν ∈ {0.02, 0.03, 0.04}. 과다 라벨 하한 0.04 와 같은 값을 고르면 게이트가 라벨을 따라가게 되므로 결과에 그 사실을 명시한다(P1-3 6장 V3 근거와 같은 주의).
- 정답 라벨(truth-FP, 정상/과다/중간)은 P1-3 V3 의 정의(6장 V3 세부 2차 재정의)를 **그대로** 재사용한다(새 라벨 정의 없음 → 라벨을 대안에 맞춰 바꾸지 않음).

### 5.2 ② G2 — 검증 손실 판정만 교체 (임계치 양방향 고정)
| ID | 대안 | 동작 | 장점 | 약점(사전 고지) |
|---|---|---|---|---|
| 현행 | 악화만 | `vc/va > 3` → FAIL | — | R5·R6 미충족 |
| **G2-A** | 양방향 FAIL | `vc/va > 3` 또는 `< 1/3` → FAIL | 단순, 대칭 | 검증 손실은 다른 데이터의 값(2.2-3) → 레거시 v1 에서의 첫 승격마다 force 필요, 정상끼리도 optical 은 2.42배(2.4) → force 습관화 위험 |
| **G2-B (권장)** | 낮은 쪽은 WARN·별도 표시 | `> 3` → FAIL(현행), `< 1/3` → **WARN**, 메시지 "검증 손실이 활성 대비 1/N — 활성 모델 비정상 또는 후보 과적합·누출 의심, 사람이 검토" | auto 는 막고(WARN) 수동은 force 없이 진행하며 근거를 남김(P1-3 7장 4 와 같은 처리) | WARN 이 잦으면 무시될 수 있음(R7 에서 WARN 비율 측정). 원인(활성 비정상 대 후보 누출)을 구분하지 못함 |
| G2-C (정보, 선택) | 같은 데이터 재구성 오차 비교 | G3 가 이미 계산한 게이트 데이터 점수에서 후보·활성의 MSE 중앙값 비 `m_c/m_a` 와 후보의 (게이트 MSE 중앙값 / 자기 val_loss) 를 `data` 에 **기록만** | 같은 데이터·같은 시점 비교라 2.2-3 의 문제를 피함. 후보 과적합은 두 번째 비로 드러날 수 있음 | 판정 기준 없음(정보), 게이트 데이터에 장애가 섞임 |

- G2-B 의 "WARN" 은 G2 의 상태를 WARN 으로 두는 것(종합 WARN → auto 차단). G2 의 임계치 FAIL 과 같이 나오면 FAIL 이 우선.
- **legacy 표시(선택, 11장 Q8)**: 활성 메타에 `baseline_port_median` 이 없으면(P1-1 이전 레거시, `retrain_policy.py:216` 과 같은 판단) G2 메시지에 "활성 = 레거시 기준(검증 손실 비교 신뢰 낮음)" 을 덧붙인다. 판정은 바꾸지 않음.

## 6. 검증 계획과 판정 기준 (제안 — 11장 결정 후, 데이터를 열기 전에 확정)

### 6.1 G3 평가 (P1-3 V3 와 같은 틀, 시드만 새것)
- 게이트 데이터: **60포트 × 4일**(규칙 B 기준선 1일 + 판정 3일 = 180포트·일), 장애 밀도 2종(기준 7일 간격, 잦음 2일 간격). 트랙 2. P1-3 V3 와 같은 생성 조건(`check_promotion.v3_table`).
- 모델: P1-3 의 `promo_s101`·`promo_s103`(운영 레시피, 기존 학습 산출물 — 평가 데이터가 아님). 후보 풀 5개·활성 2가지((a) v1 + 기본, (b) 정상 v2 = 후보 ①)·truth-FP 라벨 **P1-3 V3 그대로**.
- 각 조건에서 C4'(참고)·G3-A(δ 격자)·G3-C(ν 격자)·(G3-B 는 Q1 결정 시) 를 모두 계산(같은 알람에서, 판정식만 다름).
- **개발**: 시드 7·11(V3 탐색과 같은 조건 — 이미 열린 개발 데이터라 선택에만). **근거**: 시드 **79·83·89**, 1회.

### 6.2 G3 선택 규칙 (개발 시드 7·11)
대안·값 조합 (Gk, x) 은 다음을 **모두** 충족해야 후보:
1. 정상 라벨 후보: 모든 조건·(a)(b) 에서 FAIL **0건** (R2)
2. 과다 라벨 후보: (b) 에서 FAIL 아닌 경우 **0건** (R1)
3. 과다 라벨 후보: (a) 에서 PASS **0건** (R3 — 절대 WARN 경로가 그대로라 대부분 현행과 같음)
4. 두 모델(`promo_s101`·`promo_s103`) 모두 1~3 충족(P1-3 V3 집계 규칙)

후보가 여럿이면(제안): 같은 대안 안에서는 1~4 를 만족하는 **가장 큰 δ(ν)**(정상 후보를 잘못 FAIL 시키지 않을 여유가 가장 큼), 대안 간에는 **G3-A < G3-C < G3-B**(코드 변경이 작은 순). **후보 0개 → ① FAIL**, 근거 시드를 열지 않음(재선택·조합 금지).

### 6.3 G3 근거 판정 (시드 79·83·89, 1회)
- 선택된 (Gk, x) 와 C4' 를 같은 실행에서 계산. **PASS** = 6.2 의 1~4 를 근거 시드에서 충족. 과다 라벨이 전 조건에 없으면 판정 불가(= FAIL 과 같은 후속).
- **결과별 후속(사전 고정)**: PASS → (Gk, x) 를 선택 키로 구현(U4)하고 G3 를 **판정**으로 복귀할지는 11장 Q2. FAIL·판정 불가 → G3 는 정보·보조 신호 유지, 재설계로 다시 고르지 않음.

### 6.4 G2 평가
- **사례 생성**(새 학습, 학습 데이터 시드 **107·109·113** × 학습 난수 0·1 = 정상 후보 6개/트랙, P1-5 R0 레시피 = 운영 레시피):
  - **N (정상 쌍)**: 6개 중 순서쌍 30개(후보, 활성) — R7.
  - **L (레거시 활성)**: 활성 = `models/` 의 v1 메타, 후보 = 정상 6개 — R5(V5 와 같은 유형).
  - **K (누출 후보)**: 같은 데이터 시드로 **홀드아웃 포트를 학습에도 포함**한 학습(검증 = 학습의 부분집합) 3개(107·109·113 × 난수 0), 활성 = 같은 시드의 정상 후보 — R6. (누출이 실제로 검증 손실을 1/3 미만으로 낮추는지는 **모름** — 그것이 측정 대상)
  - **W (악화 후보)**: 짧은 학습(1에폭) 3개, 활성 = 정상 후보 — 현행 FAIL 경로 회귀 확인.
- 개발/근거 분리: 학습 난수 0 의 사례로 개발(값·메시지 확인), 학습 난수 1 의 사례로 근거 1회. (G2 는 메타 값만 비교하므로 "평가 시드" 대신 학습 산출물을 나눔)
- **G2 판정 기준(제안)**: G2-A — N 에서 FAIL 0, L 에서 FAIL 전부, K 에서 FAIL ≥ 1/3(누출 발생 여부와 별개로 기록), W 에서 FAIL 전부. G2-B — N 에서 FAIL 0·WARN 비율 기록(≤ 10% 권장), L 에서 WARN(또는 FAIL) 전부, K 에서 PASS 아님 ≥ 1/3, W 에서 FAIL 전부. **K 의 기준은 누출이 검증 손실을 낮추지 않으면 충족 불가 — 그 경우 "R6 은 검증 손실 비율로 잡을 수 없음" 으로 보고**(값을 낮춰 맞추지 않음).
- G2-C 는 판정 없이 N·L·K·W 에서 두 비율을 기록(정보).

### 6.5 변경 이력 규칙
- 11장에서 6장 값을 확정하면 그 시점의 열린 데이터를 12장에 기록. 이후 변경은 **근거 데이터(79·83·89, 학습 난수 1 사례)를 열기 전**에만, 사유·이미 본 데이터를 기록. 개발 결과를 본 뒤 바꾼 기준은 "탐색" 표시.
- 근거를 연 뒤에는 기준·대안·값을 바꾸지 않는다. 필요하면 새 시드로 별도 차수.

## 7. 승격 동작에 미치는 영향 (최소 변경 원칙)
- **기본 동작 불변**: 새 판정은 `RetrainPolicy` 선택 키로만 켠다 — `gate_g3_rule = "ratio"`(기본, C4') / `"delta"` / `"new_alarms"`, `gate_g2_val_loss = "worse"`(기본) / `"both_fail"` / `"lower_warn"`. 기본값에서 `check_g2`·`check_g3`·`compare_with_active` 출력과 기존 테스트 기대값이 **바이트 단위로 같아야** 한다.
