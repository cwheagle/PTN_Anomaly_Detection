## 1. 배경과 범위
- P1-3 V1(운영 레시피) PASS 였지만 V2(오탐 억제형 오탐 ≤ 0.02) FAIL, 126개 정책 격자 재선택에서도 충족 0개 → 오탐 억제형 **임시 채택**, C1 은 시뮬레이션에서도 미달(P1-3 설계서 6장).

## 2. 조사 결과 (코드·기록, 2026-10-07)

### 2.1 임계치 산출 경로 (코드 사실)
1. `Trainer.train()` 은 학습 CSV 로 `train_sequences` 를 만들고(스케일러 fit), 검증 CSV(운영 레시피에서는 **홀드아웃 포트**)는 `val_loader` 로 **조기 종료·best weight 선택**에만 쓴다(`trainer.py:93-105`, lessons #6·#25).
2. 학습 후 `_save_metadata(train_sequences, …)` 가 **학습 시퀀스** 전체의 마지막 시점 MSE 를 구해 `np.percentile(mses, threshold_percentile)` 를 임계치로 저장한다(`trainer.py:234`, `:289-310`). `threshold_percentile` 은 `MODEL_CONFIG` 99.5(`src/config.py.example:52`).
3. 홀드아웃 포트 데이터는 임계치가 아니라 드리프트 기준값(`baseline_port_median`/`p90`, `trainer.py:229-233`)에 쓰인다.
4. 운영 알람은 `alerting.dynamic_threshold`: 최소 임계치 = 전역 임계치 × `threshold_scale`(오탐 억제형 3.0), 동적 = 과거 평균 + `sigma_k` × 표준편차(오탐 억제형 2.0), 과거 평균이 최소 임계치를 넘으면 상한 = 최소 임계치 × `dyn_cap`(`src/pipeline/alerting.py:95-100`). 따라서 **전역 임계치가 작으면 오탐 억제형의 바닥(×3.0)도 같은 비율로 낮아진다**.
5. 홀드아웃 구성: `train_window.is_val_port` = md5(`salt|ip|cid|lid`) < 0.10, salt 기본 `"ptn"`(`src/data/train_window.py:43`, `retrain_policy.py:30-31`). 시뮬레이터 기본 포트(`ip_prefix 10.20.0.`, 4노드 × 10포트 = 40포트)는 데이터 시드와 무관하게 **같은 포트 키** → 데이터 시드 101·103 의 홀드아웃 포트 구성은 동일(약 4포트, 해시라 정확한 수는 실행 로그로 확인 필요).

### 2.2 기존 가설과의 차이 (정정 필요)
- plan.md P1-5 행과 P1-3 설계서 6장 "원인 추정"은 "임계치가 **검증 포트 홀드아웃의 99.5 백분위**" 라고 적었으나 **코드와 다르다**(2.1-2). 홀드아웃이 작아서 생길 수 있는 영향은 **조기 종료가 작은 표본의 검증 손실로 best epoch 를 고르는 경로**(가중치 → 학습 시퀀스 MSE 분포 → 임계치)뿐이다. 이 경로도 미검증이다.
- 이 문서는 정정된 사실을 전제로 하며, plan.md·P1-3 설계서 문구 정정은 별도 커밋으로 한다(11장 Q1).

### 2.3 "실험 0.010 대 운영 0.029" 비교는 교란되어 있다
| | P0-2 실험 모델 (0.010) | P1-1 7.2 truth (0.015 / 0.029) | P1-1 7.2 auto (0.008 / 0.012) | P1-3 운영 v2 (0.029) |
|---|---|---|---|---|
| 정제 | 정답(truth) | 정답 | 규칙 B (A∪B 아님) | **A∪B**(v1 자기 알람 + 규칙 B) |
| 검증 분할 | 시간(후반) | 시간 | 시간 | **포트 홀드아웃 10%** |
| 학습 포트·기간 | 40포트 × 앞 80% | 동일 | 동일 | 약 36포트 × 21일 전체 |
| 실행 | 1회 | **반복 2회** | 반복 2회 | 학습 시드 2개 × 평가 시드 3 |

- 같은 레시피 반복(truth)만으로 0.015 ↔ 0.029 가 나왔다 → **학습 난수에 의한 분산이 이미 C1(0.02) 경계를 넘나드는 크기**다(2회뿐이라 분산 추정은 불가).
- 따라서 "운영 레시피라서 0.029" 라고 볼 근거가 없다. 원인 후보: (a) 학습 난수, (b) 학습 데이터 시드, (c) 홀드아웃 구성(조기 종료 경로), (d) 분할 방식(포트 대 시간: 학습량·검증 성격이 다름), (e) 정제 방식(A∪B 대 B 대 truth), (f) in-sample 백분위 자체의 편향(학습 데이터 과적합으로 꼬리가 짧아짐 → 임계치 낮음).
- 관찰값(V4 로그): 운영 v2 전역 임계치 traffic s101 0.6266 / s103 0.6000, optical 0.1643 / 0.1418 (비 1.04, 1.16). 두 점뿐이라 분산 결론 불가.

## 3. 1단계 — 원인 분해 실험 E0 (먼저, 대안보다 앞)

### 3.1 기준 레시피 R0
P1-3 운영 레시피 그대로: `check_promotion.train_operational`(시뮬레이터 4노드 × 21일 noisy, A∪B 제외, 포트 홀드아웃 10% salt `ptn`, 30/64/5, 활성 v1 = `models/`), 평가 = 오탐 억제형 프리셋(배율 3.0/σ 2/댐프닝 6·4·3), 병기 = 기본 정책. 평가 데이터 = 개발 시드 7·11(6노드 × 14일, V1 과 같은 조건).

### 3.2 요인 (한 번에 하나만 바꿈, 나머지 R0 고정)
| 실험 | 바꾸는 것 | 수준 | 학습 횟수(두 트랙 1세트 = 1회) |
|---|---|---|---|
| **E0-a 학습 난수** | `train_seed`(torch·numpy) | 0, 1, 2 × 데이터 시드 101·103·105 | 9 (R0 세트, 이후 모든 비교의 기준) |
| **E0-b 홀드아웃 구성** | `split_salt` | `ptn`(R0), `p15a`, `p15b`, `p15c` × 데이터 101, 난수 0·1 | +6 |
| **E0-c 분할 방식** | 포트 홀드아웃 → 시간 분할(전 포트 앞 80% 학습, 뒤 20% 검증) | × 데이터 101·103·105, 난수 0 | +3 |
| **E0-d 정제 방식** | A∪B → truth(정답 구간 제외, 진단 전용) | × 데이터 101·103·105, 난수 0 | +3 |
| 합계 | | | **21회** (소요 시간은 첫 1회로 측정해 보고, 미측정) |

- 데이터 시드 105 는 새로 추가(101·103 만으로는 데이터 요인 분산 추정 불가). 102 는 P0-2 민감도 평가에서 연 시드라 학습에 쓰지 않는다.
- truth 정제(E0-d)와 오라클(3.3)은 **진단 전용**이며 운영 코드로 옮기지 않는다(lessons #22).

### 3.3 측정 지표
각 학습 모델(트랙별)에 대해:
1. **전역 임계치**, best epoch, best val_loss, 학습 시퀀스 수, 홀드아웃 포트 수.
2. 개발 시드 7·11 평균: 오탐 억제형의 **오탐/포트·일·이벤트 F1·조기 탐지율·리드타임 중앙값**, AUPRC(순위 품질, 임계치와 무관한 비교용), 기본 정책 병기.
3. **오라클 임계치 대입**: 별도 정상 기준 데이터(시드 **211**, 4노드 × 14일, 정답 구간 제외 = truth)에서 그 모델의 마지막 시점 MSE 99.5 백분위를 **out-of-sample 임계치 th\*** 로 계산 → 같은 모델 가중치에 th\* 를 대입해 2 를 다시 측정. "같은 가중치·더 나은 임계치 추정" 이 오탐을 얼마나 바꾸는지 본다.
4. **in-sample 편향**: (학습 시퀀스 99.5 백분위) / (th\*) 비율. 1 보다 작으면 in-sample 임계치가 낮게 잡히는 것.
5. 재계산 검증: 도구가 학습 시퀀스로 재계산한 임계치 = 메타의 `threshold`(상대 오차 < 1e-6) — 도구가 운영 산출식과 같다는 증거(#31).

### 3.4 E0 판정 질문 (기준 값은 6.1 에 사전 고정)
- **Q-A 임계치 불안정이 있는가**: R0 세트(9회) 안에서 트랙별 임계치 max/min, 변동계수.
- **Q-B 오탐 분산을 임계치가 설명하는가**: R0 세트의 오탐 표준편차가 th\* 대입 시 얼마나 줄어드는가(설명 몫 = 1 − SD(th\*) / SD(자체)), th\* 대입 시 오탐 평균.
- **Q-C 요인별 효과**: E0-b(구성), E0-c(분할), E0-d(정제) 각각의 R0 대비 짝지은 오탐 차이(같은 데이터·난수끼리).
- **결정표**:

| E0 결과 | 다음 단계 |
|---|---|
| Q-B 충족(임계치가 주원인) | 2단계 T1·T3 (임계치 산출원 변경) 우선, T2 병행 |
| Q-B 미충족, Q-C 에서 구성 또는 분할 효과 충족 | 2단계 T2 (홀드아웃 비율·최소 포트 수) 만 |
| 둘 다 미충족(주원인 = 학습 난수에 의한 가중치 차이) | **2단계 진행 안 함.** 결과 보고 후 사용자 결정(여러 학습 실행 중 선택·앙상블 등은 P1-5 범위 밖) |

## 4. 2단계 — 대안 비교 (E0 결정표가 허용한 것만, 한 번에 한 가지)
각 대안은 R0 에서 **하나만** 바꾼다. 학습 세트 = 데이터 101·103·105 × 난수 0·1 (6회, R0 세트의 같은 6개와 짝 비교).

| ID | 대안 | 바꾸는 것 | 재학습 | 채택 시 운영 코드 영향 |
|---|---|---|---|---|
| **T1** | 홀드아웃 백분위 | 임계치 = **홀드아웃 포트** 시퀀스의 99.5 백분위 (out-of-sample). 가중치·학습 데이터 불변 | 불필요(저장 모델 + 홀드아웃 CSV 로 사후 계산) | `trainer.py` 임계치 산출원 선택 인자(기본 = 현행) |
| **T2** | 홀드아웃 비율·최소 포트 | `val_port_fraction` 0.10 → **0.20**, 그리고 홀드아웃 포트 **최소 8개** 미달 시 학습 중단(SKIP) — 임계치 산출원은 현행(in-sample) | 필요 | `RetrainPolicy` 값·가드(`retrain_policy.py`, `train_window.py`) |
| **T3** | 학습 포트의 시간 후반 백분위 | 학습 포트를 시간으로 나눠 앞 80% 로 학습, **뒤 20% 의 99.5 백분위**를 임계치로 (조기 종료는 현행 홀드아웃 그대로) | 필요 | `trainer.py` + `data_collector.py` 분할 |
| T4 (보류) | 포트별 정규화 | 점수 또는 임계치를 포트별 기준값으로 정규화 | 필요 | 추론·알람 경로(`inference.py`·`alerting.py`) 변경 — **T1~T3 모두 실패하고 사용자가 승인할 때만 별도 설계** |
| (제외) | 백분위 값 변경(99.5 → 99.9 등) | — | — | 정책의 `threshold_scale` 과 사실상 같은 효과이며 P0-2·P1-3 격자에서 이미 탐색 → 재탐색 금지 |

- T1 은 홀드아웃이 약 4포트이면 표본이 작아 오히려 불안정할 수 있다 → 결과에 "홀드아웃 포트 수 대 임계치 분산" 을 함께 보고. T1 이 분산 기준만 실패하면 T1+T2 조합을 **새 대안으로 다시 정의하지 않는다**(사후 조합 금지, 필요하면 11장 결정으로 다음 차수에).
- 정책은 오탐 억제형 프리셋 고정(재튜닝 없음). 기본 정책 수치는 병기만.

## 6. 판정 기준 (11장 결정 후, 데이터를 열기 전에 확정)
> 아래 값은 **제안**이다. lead/사용자 확인(11장 Q2) 후 이 문서에 "확정" 표시와 날짜·커밋을 남기고, 그 뒤에는 변경 이력 규칙(6.4)만 따른다.

### 6.1 E0 (개발 시드 7·11)
| 질문 | 충족 조건 | 근거 |
|---|---|---|
| Q-A 불안정 있음 | R0 세트 9회에서 어느 한 트랙이라도 임계치 max/min ≥ **1.25** | V4 의 두 점이 1.04·1.16. 정책 바닥이 ×3.0 이므로 1.25 배면 바닥이 의미 있게 움직임(추정) |
| Q-B 임계치가 주원인 | 설명 몫 ≥ **50%** (오탐 SD 가 th\* 대입 시 절반 이하) **그리고** th\* 대입 시 오탐 평균 ≤ 0.02 | 절반 이상이면 "주원인" 이라는 표현이 성립 |
| Q-C 요인 효과 | R0 대비 짝 오탐 차이 평균의 절댓값 ≥ **0.008** 이고 짝의 2/3 이상에서 같은 부호 | 0.008 ≈ P1-3 의 시드별 오탐 SD(0.007) 보다 약간 큼 |

- E0 는 판정 결과와 무관하게 **모든 수치를 보고**한다(Q-A 미충족이어도 Q-B·Q-C 는 계산).

### 6.2 2단계 선택 규칙 (개발 시드 7·11, 대안별 6회 평균)
대안 Tk 는 다음을 **모두** 충족해야 후보:
1. 오탐 억제형 오탐 평균 ≤ **0.02**
2. 이벤트 F1 평균 ≥ R0 − 0.03
3. 조기 탐지율 평균 ≥ R0 − 0.05
4. AUPRC 평균 ≥ R0 − 0.03 (재학습 대안 T2·T3 의 가중치 열화 감시)
5. 임계치 max/min(6회) ≤ R0 의 같은 6회 값 (불안정을 키우지 않음)

후보가 여럿이면 오탐 평균 최소 → 차이 0.003 이내면 운영 코드 변경이 작은 순(T2 < T1 < T3). **후보 0개면 2단계 FAIL** 로 보고하고 검증 시드는 열지 않는다(재선택·조합 금지).

### 6.3 검증 (새 시드 53·59·61, 1회)
선택된 Tk 와 R0 를 같은 실행에서 함께 측정(짝 비교). **PASS** = Tk 가 6.2 의 1~4 를 검증 시드에서도 충족(2~4 는 같은 실행의 R0 대비). 롤링 규칙·고정 임계치·항상 알람 베이스라인 병기(#23). FAIL 이어도 기준·대안을 다시 고르지 않는다.

### 6.4 변경 이력 규칙
- 6장 확정 후 기준 값을 바꾸려면 **새 데이터를 열기 전**에만, 12장에 날짜·사유·이미 본 데이터 범위를 기록한다(lessons #37).
- 개발 시드 결과를 본 뒤 바꾼 기준은 그 개발 결과를 "탐색" 으로만 표시하고, 근거는 미개봉 검증 시드 1회에서만 얻는다.
- 검증 시드를 연 뒤에는 기준·대안·정책을 바꾸지 않는다. 필요한 수정은 새 시드로 하는 별도 차수다.

## 7. 정책 C1·운영에 미치는 영향 범위
- **V2 FAIL 은 그대로** 둔다(P1-3 기록, lessons #37). P1-5 결과는 운영 레시피에 대한 새 근거다.
- **PASS 시**: "변경된 임계치 산출 + 오탐 억제형이 시뮬레이션에서 C1 0.02 를 만족" 이라는 근거가 생긴다. 운영 적용은 새 후보를 그 레시피로 학습 → P1-3 7장 절차(게이트·사유 기록) 승격이 필요하다. 임계치 산출이 바뀌면 G2 의 임계치 비(3배) 경고가 날 수 있다(T1·T3 는 임계치를 올리는 방향으로 예상, 미검증) — 이때 force 판단은 P1-3 7장과 P1-6 ② 를 따른다.
- **FAIL / 2단계 미진행 시**: C1 은 시뮬레이션에서 계속 미달. 선택지(결정은 사용자/P0-3 합의): (i) C1 유지 + 섀도에서 확인, (ii) 더 보수적인 정책(조기 탐지 감소 감수), (iii) C1 재검토. P1-5 는 이 중 하나를 정하지 않는다.
- **운영 코드 원칙(제안)**: 실험 단계에서 `src/` 변경 없음. 채택 시에도 `MODEL_CONFIG`(`threshold_percentile` 99.5 포함)·기본 `AlertPolicy`·`config.py.example` 의 정책 기본값 불변, 활성 모델 불변. 변경은 **선택 인자(기본 = 현행 동작)** 로 추가하고 기존 골든·재현 테스트가 그대로 통과해야 한다. 기본값으로 켤지(드리프트 재학습 후보에도 적용할지)는 11장 Q5.
- **C1 의 실데이터 판정**은 P1-2·섀도에서만 한다. 이 문서의 수치는 C1 판정에 쓰지 않는다.
